# Workflow-level capability inventory (non-coding) — 2026-10-24

Sources: `n8n_custom_nodes/scripts/op-schema-catalogue.json` (25 packages, 29 node types, 1310 ops), `n8n_custom_nodes/{demos,workflows,integrations}`, gitops `origin/main` + live `kubectl get deploy -A` (2026-10-24), agent spec `12-agent-tool-scoping.md` / `11-object-model…md`.

## Ground truths that shape the design
- **Most n8n "workflows" are either CRUD demos (`demos/<module>/*.json`, ~120, all deterministic, create→read→cleanup) or the AA card-lifecycle conveyor** (`workflows/patterns|routines|atomics`, 157 routines, 159 atomics; ~80% coding). Business-level multi-module workflows outside coding are few.
- **The LLM boundary in n8n is one op: `workers.createWorker`+`workers.sendWorkerMessage`** (also `workers.chatCompletions`, `kag.askQuery`, coding `ai.*`). Every other node op is deterministic HTTP. So "no LLM in a tool" = exclude `workers.*Message`, `kag.ask*`, `strata /api/ask`.
- **Agent platform consumes canonical operations `object.verb{variant}`**, not MCP names: `knowledge.search`, `case.create{return|complaint}`, `case.read/comment`, `handover.*`, `party.read/list`, `order.read/list/cancel/modify`, `delivery.read/redirect/report_problem`, `payment.list/refund`, `offering.read/list/availability`, `rule.evaluate{ID}`, `credential.verify`, `contact_point.update`, `consent.update`, `document.read{invoice}`, `policy.*`. Runner already enforces identity level, confirm-back for W/X, `verify_read` after X. Toolkits should map 1:1 onto these ops so they can be routed as `mcp` transport.
- care-bus today: 6 workers (crm, order, delivery, faq, business-rules, procedures) → enterprise-mcp/this server's `carebus` builtins → **demo-backends (stub data)**.

## Patterns to reuse for every toolkit
- **Precondition sources:** `rule.evaluate` (procedures), identity level from `credential.verify`, licence introspection, fr `projects.constraintCheck`, wipSlot/lease claim.
- **Auto-verify = read-after-write**: every mutating n8n chain already ends with a get (demos follow create→store id→get). Codify as `verify_read` with idempotency key, matching the agent runner's step 10 (`unknown_outcome` if read fails).
- **Composition already exists as `executeWorkflow` subroutines** (card-from-template, search-requirements, store-artifact) — these are the right granularity for toolkit tools.

## Gaps / risks
- KAG stack, Twenty, Signal, listmonk, maddy, improvement-loop, n8n-demo **all at replicas 0** (owner decision 2026-10-20) — toolkits on them are not live-verifiable.
- Commerce domain has no real backend — only demo-backends; value depends on tenant connectors.
- Non-coding n8n workflows are mostly CRUD showcases; workflow-level business compositions must be authored, not harvested.
