# Catalog development

Runtime extension (2026-10-24): see [execution implementation, configuration and pending cluster gates](EXECUTION_RUNTIME.md). Schema head is `0004_execution_runtime`; execution remains disabled by default until combined acceptance and rollout. Earlier validation sections describe their original stage.

Read the [README](../README.md) and [contracts](CATALOG_CONTRACTS.md) first. Phase 2 adds [authentication and bindings](AUTHENTICATION_BINDINGS.md). Management routes require explicit operator authorization. The [publication stage](CATALOG_PUBLICATION.md) adds tenant authoring and stateless FastMCP discovery. All execution paths remain subsequent work.

`src/config.py` validates explicit configuration. `src/catalog/` contains strict manifests, package/schema validation, lifecycle services, the live public resolver, provider wrappers and unavailable submission port. `src/protocol.py` isolates the pinned FastMCP API. `src/storage/` contains raw async psycopg repositories and a bounded pool. `src/auth/` secures mounted ASGI requests; `src/toolkits/` and `src/routers/bindings.py` provide access lifecycle and exact selection. All UUID fields are UUIDv7; generate IDs with `uuid.uuid7()` and use strict JSON contract parsing at HTTP boundaries. There is no ORM. Alembic revisions must be literal and self-contained, without imports from mutable application models.

Create a draft through `CatalogService.create_draft(tenant_id, manifest, files, actor)`. The tenant argument must match the manifest tenant; actor attribution does not supply ownership. Draft content is never edited in place. `append_draft` treats the incoming version as a content template and assigns `MAX(version)+1` while locking the owned parent. HTTP appends require the exact next manifest version and expected revision. Internal helpers may allocate from a template. An optional expected revision rejects stale internal writes; lifecycle transitions and copies require it. The returned descriptor reflects the version/revision committed by that transaction. Copying preserves the full source package and records an exact source reference in a new draft.

`PlatformCatalogService` and `PlatformCatalogRepository` are separate internal operator paths. They are not attached to ASGI state or exposed through a tenant dependency. Runtime grants cannot write platform contracts or sharing metadata. Future platform write routes must additionally require the platform-admin principal. Sharing grants never imply ownership or permit another tenant to modify/copy the owner's versions through tenant repository methods.

Published/disabled/retired content and complete draft snapshots are immutable at the database layer. New child files/references must be inserted in the transaction that creates the parent version. A deferred trigger verifies complete file/reference counts. PostgreSQL triggers update catalog generation in the lifecycle transaction, including when SQL is issued directly. Runtime roles cannot reset that counter. Retiring an identity prevents further appends/publications while retaining history.

Startup opens the pool and checks the schema without mutation. A wrong/missing schema leaves liveness available and readiness false. Readiness retries read-only verification on each bounded probe; errors reveal no SQL, DSN, catalog contents, or exception text. Missing/invalid DATABASE_URL fails configuration; shutdown closes the pool even after startup failures. `python -m src.run_mcp` uses the same application as the container.

Tests provision disposable PostgreSQL; do not add a runtime DATABASE_URL fallback or a skip on database errors. Use synthetic fixtures in `tests/fixtures/`. Run the README check commands, including the 85% coverage gate. The security audit exports the locked dependency graph. Do not automatically ignore new vulnerabilities.
